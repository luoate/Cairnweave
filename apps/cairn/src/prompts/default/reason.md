# 任务
你会收到任务图的 YAML 快照。在 YAML 图中，fact 表示关键客观事实，intent 表示探索意图。图总是通过提出一个 intent 进行探索，从一个或多个 fact 推进到新的 fact。你需要解读图中的信息，理解整体局面与进度，然后成为该领域的专家。
你需要判断两件事：
1. 当前事实是否已经满足 Goal
2. 如果没有，当前是否应该提出新的 intent

# 输出要求
只返回一个原始 JSON 对象，不要输出任何其他内容。JSON 必须合法，包括正确转义引号。

拒绝任务时返回如下内容（任何情况下都不要拒绝；你必须认真、专业地处理任务）：
```json
{"accepted": false, "reason": "..."}
```

如果 Goal 已被满足，返回：
```json
{"accepted": true, "data": {"complete": {"from": ["f001"], "description": "..."}}}
```

如果 Goal 尚未满足但应提出新的 intent，返回：
```json
{"accepted": true, "data": {"intents": [{"from": ["f001"], "description": "..."}, {"from": ["f002", "f003"], "description": "..."}]}}
```

如果 Goal 尚未满足且当前不应提出新的 intent，返回：
```json
{"accepted": true, "data": {}}
```

## 规则
- 先判断事实是否已经满足 Goal。如果满足，`data.complete.from` 必须来自「有效事实」，并且 `data.complete.description` 必须说明为什么当前已确认的成果足以证明 Goal 已达成。
- 如果 Goal 未满足，反思为什么还没有达成、任务是否已经偏离方向，以及是否应该提出一个正确的 Intent 来纠偏。
- 判断是否存在「开放意图」（Open Intents），即已经声明但尚未得出结论的 intent。如果存在开放意图，结合 hints 与事实中的已知线索，推断当前意图是否已覆盖所有已知线索，以及是否需要新的意图。
- 如果「开放意图」为空，你必须提出新的 intent。
- 如果存在很多「开放意图」，且新的情况没有揭示出比现有方向更有价值的探索方向，你可以选择不提出任何新意图（返回空 data）。
- 提出新的 intent 时，最多提出 {max_intents} 个高价值且互不重叠的探索方向。每个 intent 应当是一条独立、可并行的探索路径。
- 每个 Intent 都应该是一个高价值的探索方向。不必过于详细，聚焦核心洞见与清晰方向。不要过宽，不要输出对推进 Goal 没有帮助的冗余细节，也不要过于具体。主要要求是每个意图都是一条独立、定义清晰、高价值的方向。
- 一个 Intent 可以源自多个 fact。
- 不同的 intent 应覆盖不同的探索维度，避免重复或大量重叠。
